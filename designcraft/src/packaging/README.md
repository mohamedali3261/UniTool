# Carton dielines

Open **المصمم → قوالب العلب والمقاسات**. Supports rectangular reverse-tuck cartons and a separate hinged-lid tray structure. The original reverse-tuck construction includes: front/side/back/side panels, glue flap, opposite top/bottom covers and four tapered dust flaps.

All geometry is in millimetres. Defaults: 80 × 120 × 35 mm with 12 mm glue/tuck tabs. Flat sheet width = glue + 2×width + 2×depth + 20 mm; height = height + 2×(depth+tuck) + 20 mm. The extra 20 mm is a 10 mm outer margin on each side, not artwork bleed. Dimensions and tab proportions are validated. Paper guidance checks A4/A3 in both orientations.

The preview, SVG, vector PDF and native Fabric objects share `geometry.ts`. Standalone PDF contains only vector cutting/creasing guides at exact custom physical page size; SVG optionally includes dimension annotations. These standalone files do not include subsequent artwork. Print actual size / 100%, never fit-to-page.

Opening a template creates a separate design, preserving existing projects. Native guides cannot be deleted/unlocked through the layers controls. Metadata, silhouette and six-decimal Fabric serialization persist. The canvas-level cut mask confines all added images, text, shapes, groups and background to the unfolded carton outline, not individual faces. Artwork can cross folds. Generic pixel resizing and incompatible exact-size templates remain blocked to protect physical scale. Use the carton bar’s Edit dimensions action to adapt the existing artwork to new nominal dimensions.

**Print export** in the editor includes the complete clipped artwork, with optional cut/crease guides:
- SVG: exact-mm sheet, vector text/shapes and regenerated vector guides. Original fonts must be available; embedded raster images retain their source detail.
- PDF: exact-mm page, rasterized artwork at 300 or 600 DPI plus vector manufacturing guides. Appearance is fixed without requiring the recipient's fonts. This is not an all-vector artwork PDF.
- PNG: exact calculated pixel dimensions and real pHYs metadata (300/600 DPI). Pixel rounding means nominal physical size is approximate, unlike SVG/PDF.

Print dimensions do not depend on editor zoom/pan. Rendering uses a separate canvas and a full-resolution mask. Rasters are limited to 40 million pixels / 16,384 pixels per side; oversized requests fail visibly rather than silently downsampling. Low-resolution placed images trigger effective-DPI warnings: upsampling does not recover missing detail. Resized legacy canvases are rejected for physical print export. The general PDF action also routes cartons through the 300-DPI print pipeline; ordinary non-carton exports are unchanged. Generic PNG/JPEG exports remain screen/pixel exports: use **Print export** for DPI metadata.

**Manufacturing limits:** nominal geometry only, without paper-caliper, crease, tooling or machine compensation. No automatic bleed/safe-area generation or spot-color production separation. Exports are RGB, not certified CMYK or PDF/X. The small template-dialog assembled view is a proportional illustration. The editor’s interactive 3D view uses nominal hinged geometry, not a collision/physical fold simulation. Prototype, measure and confirm allowances/production suitability with your printer before production.

Checks: `npm run test:designcraft` and `npm run test:designcraft:browser`. Browser QA uses `DESIGN_QA_URL` and optional `STUDIO_CHROMIUM_PATH`; simulation is not physical-device/printer certification. PDF support is locally bundled and loaded on demand; no new runtime dependency is added.

The public dimensions UI uses **length × width × depth** (طول × عرض × عمق), with tab sizes under advanced settings. For compatibility with existing saved projects, the internal `height` key remains the assembled box length (vertical face axis); `width` and `depth` retain their existing axes. No saved project geometry or physical export scale is changed by this terminology update.

## Perfume starter cartons

Editable 30 / 50 / 100 ml capacity labels select these **suggested nominal** length × width × depth sizes: 95 × 40 × 30, 115 × 50 × 35 and 140 × 60 × 45 mm. These are not standardized bottle dimensions, measured samples, guaranteed internal sizes, or molds for manufacturing glass bottles.

`PerfumeTemplates.tsx` offers measured capped-bottle sizing with per-side clearance (default 2 mm). `perfume.ts` computes each nominal dimension as measured dimension + 2×clearance, rounds dimensions to 0.01 mm, and limits tabs to valid proportions (rounded down). It does not compensate for board caliper, inserts, scoring or machine tolerances. All nominal dimensions and tabs remain editable; existing projects retain their old geometry. The dialog includes a dimension review and assembly checklist. Templates create new blank native designs, not destructive resizing of existing artwork.

Tests verify opposing panel dimensions, cover depth, dust-flap gap, crease count, sheet margins, invalid measurements and native persistence of customized preset sizes. Browser checks cannot certify physical assembly or weight-bearing performance. Perfume bottles are heavy and fragile: tuck closures may need an insert or reinforced base approved by the packaging manufacturer. Validate paper prototypes and production-stock samples with the actual capped bottle before a production run.

## Packaging atelier and editable artwork

The dimensions dialog has responsive capacity cards, section navigation, coordinated appearance controls, and a live artwork/dieline switch. Choosing a perfume starter also selects a suggested design (30 ml velvet rose, 50 ml emerald garden, 100 ml golden night). A blank option preserves the original guide-only workflow. Users can select another appearance, customize brand/fragrance text, accent color and printed capacity, or reset settings.

`artwork.ts` generates native editable rectangles, circles and textboxes independently of the locked manufacturing guides. The live flat preview uses the same primitives; the small assembled view is only a proportional illustration. All artwork is still clipped to the carton silhouette and can be edited in the main editor. No flattened design image, external artwork downloads or new dependencies are needed. Golden accents simulate RGB colors, not metallic ink or foil. Template text is placeholder branding, not verified regulatory labeling or ingredients.

The optional 3 mm safe-area overlay is a preview-only suggestion for the four body panels. It is not bleed, manufacturing compensation or an exported guide; ask the printer for production specifications. Template-dialog SVG/PDF buttons intentionally download dielines only; complete artwork print downloads are available after opening the editor. Appearance customization does not alter physical carton dimensions.


## Interactive 360° carton assembly

After creating/opening a **carton project only**, choose **معاينة ثلاثية الأبعاد 360° / 3D preview · 360°** in the carton bar. Ordinary design projects do not get this action. The lazy-loaded modal renders the current artwork snapshot on a 13-piece reverse-tuck model: four body panels, glue flap, two lids, two tuck tabs and four tapered dust flaps. Body and flap vertices, hinges and texture coordinates use the same nominal millimetre geometry as the editable dieline. The closed six exterior planes have exactly the nominal width/length/depth, including asymmetric and customized dimensions.

Drag freely with mouse or touch (TrackballControls has no polar-angle limits); wheel/pinch zooms, right-drag or two fingers pan. Top/bottom and four side presets, perspective/reset, and keyboard arrows / + / − / Home are available. The folding slider stages body/glue, dust flaps, lids, then tuck tabs; unfold/assemble buttons jump to the endpoints. Folding/resize fitting preserves viewing direction. There is no opaque floor hiding the underside, and no automatic spinning or inertial camera motion.

`preview3d/assembly.ts` defines the millimetre hinge hierarchy. `mesh.ts` triangulates actual flap polygons with printed outward faces, unprinted inward faces and cardboard-colored cut edges. Closure layers are offset inward to keep dust/glue/tuck surfaces below the outside panels. **0.35 mm is an approximate visual thickness, not a measured stock input or a manufacturing allowance.** This remains an idealized nominal folding preview, not crease deformation, contact/collision analysis, glue behavior, load testing, internal-clearance certification or photorealistic/CMYK proofing. Prototype in the intended stock and check with the manufacturer.

`atlas.ts` snapshots through a separate Fabric canvas with six-decimal serialization, omits `packaging-*` guides, preserves the silhouette/image crop/text/artwork, and ignores editor zoom/pan. High preview quality is capped at 4096 pixels per edge and 16 million pixels on desktop / 8 million on mobile; Balanced is capped at 2048 pixels per edge / 4 million pixels. Both cap sampling at 32 pixels/mm and round backing-store sizes down to respect the area budget. This is a screen preview, not a print-resolution replacement. UV normalization uses the actual rounded raster size. No source selection, objects, viewport, print scale, undo state or saved project are changed. No preview raster is persisted. Reopen the modal to refresh after editing.

The renderer updates on interaction/resize rather than running an idle animation loop. Closing/reloading releases GPU geometry/materials/textures, controls, observers, listeners, animation frames and the temporary canvas. WebGL/image/dimension failures show a retryable error without altering the source. Browser checks cover the six artwork faces and front left/right orientation, actual image crop, guide removal, source isolation, desktop orbit, mobile touch, folding, reopen cleanup, Arabic/English and unavailable/lost WebGL contexts. Geometry checks cover flat-sheet area/hinge alignment, finite UVs, outward normals and nominal closed bounds at minimum, default, custom and maximum sizes.


## Resize an existing carton design

**تعديل المقاسات / Edit dimensions** in the compact carton bar edits the current project’s length, width and depth in millimetres; it does not create a blank template or replace artwork. Preview and print exports immediately use the updated metadata, regenerated locked cut/crease guides and silhouette. Saved projects retain their identity; undo/redo includes nominal geometry as well as native artwork. Closure tabs are reduced when necessary to remain valid for smaller dimensions.

`resize.ts` anchors objects to their corresponding body/lid/flap region using their existing center, maps relative positions to the resized region, and fits axis-aligned rectangles/background fills in both axes. Images, text, groups and other shapes scale uniformly to retain their existing proportions. Native object IDs, text contents, colors, crop, rotation, flips, grouping, visibility/locks and relative clip paths remain editable; absolute clip paths follow the same placement transform. Sheet-wide backgrounds and canvas background/overlay images adapt across the sheet. No artwork is flattened, regenerated from template defaults or duplicated. The view fits the new sheet after applying.

This is layout adaptation, not semantic re-typesetting or a guarantee that arbitrary artwork spanning multiple folds will maintain exact registration through every dimensional change. Review tight spacing, fold-spanning artwork, clipping and the 3D preview after large/asymmetric changes, then prototype before production.

The advanced-designer-tools **section and launcher are removed** from the editor. Debounced, bounded recovery snapshots and unsaved-work/unload protection still run through the headless `useStudio` hook, without restoring that toolbar or modal. Print help no longer points to the removed section. Browser coverage verifies same-project native artwork retention, proportion preservation, minimum dimensions/tab clamping, invalid/cancel isolation, undo/redo, current-size 3D and physical SVG export, persistence, compact mobile actions and headless recovery/storage behavior. Retired advanced-modal UI tests are replaced by headless recovery checks; the underlying pure core remains unit-tested.


## Dedicated packaging studio and material preview

Open **تصميم العلب / Packaging studio** or `/designcraft.html#packaging`. This is a separate, directly addressable dashboard page with its own gallery, search and compact/tall/wide filters; hash navigation survives refresh and browser Back/Forward. Choosing a card opens its editable size/artwork setup, then the **same standard Fabric canvas editor**, not a second design engine. The quick-entry card now routes to this page. Ordinary design creation remains available separately.

`catalog.ts` defines 12 validated reverse-tuck starters: gift and mini cubes, cosmetics, perfume, serum, candle, tea, tall slim, flat soap, wide chocolate, pencil and wide gift cartons. These are **different proportions and nominal sizes of the supported reverse-tuck construction**, not claims of new mailer, sleeve, gable, hexagonal or crash-lock manufacturing mechanisms. Non-perfume starters use generic editable collection/product labels instead of perfume capacity/concentration text. Sizes are suggestions, not measured product-fit or load-bearing guarantees. Gallery cards now lazily render the actual assembled geometry and native artwork; see the family gallery section below.

High-quality 3D preview now uses the larger bounded artwork atlas, anisotropic mipmapped sampling, pixel-budgeted screen supersampling, neutral tone mapping, a locally generated studio reflection environment, directional self-shadowing and deterministic micro-grain. Matte and satin finishes are visual material choices only; they do not change artwork, print data or manufacturing geometry. Satin highlights are not actual foil/varnish separations. The environment, paper grain, shadow maps, pending paint frames, renderer and temporary artwork resources are released on close/reload; the idle view does not run an animation loop. Balanced mode reduces the texture, shadow and screen budgets. Changing clarity preserves the chosen fold stage and finish. No remote HDR image, AI-generated product photo, raster asset download, saved high-resolution preview or new dependency is required. Low-resolution placed images still have limited real source detail.

The **Save & storage** page now uses a concise summary, usage meter, searchable/sortable thumbnail cards and compact cleanup actions. Native backup download, project opening, persistent-storage request, recovery cleanup and destructive confirmation dialogs remain functional. Carton card dimensions are displayed in millimetres; regular designs retain pixels. Memory-only fallback is explicitly marked temporary. Long explanatory copy is removed from the main view; essential local-only and deletion warnings remain. The site-wide `/storage.html` backup page also has a compact action-first layout and optional coverage details; archive format, restore behavior and project/recovery retention policies are unchanged.


## Family gallery and independent projects

`/designcraft.html#packaging` now has **28 editable starters** in product-carton, pizza, bakery and hinged-mailer sections. Ordinary designs remain in **My projects**, without packaging projects mixed into their count or search. Each packaging section has its own saved-project shelf/search and its own templates; **All boxes** intentionally aggregates all packaging families. Legacy `category: packaging` projects without structural metadata stay visible under product cartons, using their saved flat thumbnail rather than an invented 3D structure. Storage/backup remains the global overview; filtering a family never deletes/moves projects, and no scoped list is passed to global destructive storage operations.

- Product cartons: the original 12 reverse-tuck presets.
- Pizza: 6, 8, 10, 12, 14, 16, 18, 20 and 24 inch square nominal bases (rounded to hundredths of a millimetre).
- Bakery: 150, 200, 250 and 300 mm square bases, with suitable initial wall heights.
- Hinged mailers: three rectangular base sizes. This is the same hinged tray mechanism, **not a certified interlocking shipping box**.
- Custom dimensions in a family retain that family's construction/category. Hinged bases accept 100–650 mm width/length, walls 20–150 mm high, and lid flaps 5–30 mm (no more than 70% of wall height). These are suggestions, not verified product fits or inside clearances.

`hinged.ts` supplies a genuinely different connected cut net: base, four walls, four corner wings, hinged lid and three inward lid flaps. It has 13 physical pieces and 12 folds, rather than stretching the old reverse-tuck dieline into a pizza shape. The six face rectangles, editable artwork, resize mappings, UVs and 3D hinges all use these physical millimetre coordinates. The unused legacy glue allowance is hidden for this construction. Corner wings must be secured appropriately for the board; prototype before production. Neither construction is a production-certified die or food-contact/material specification.

Native kraft/brand/label artwork remains individual editable Fabric objects, not a generated photograph. Gallery cards use **one lazy shared WebGL renderer**, a serialized visible-card queue, 600×440 WebP snapshots, a bounded 1024-edge/1 MP artwork atlas and transient object URLs. The model, environment, geometry, textures, shadows, surfaces and URLs are disposed on gallery exit; canceled/offscreen jobs do not create background models. Photos are session-only and are **not** saved into project storage or backups. Saved project cards use the project's own native artwork. Simple SVG/saved-thumbnail fallbacks remain usable without WebGL.

Large pizza nets may exceed the existing 40 MP / 16384-pixel raster print budget at 300/600 DPI. The print dialog keeps this limit explicit; physical vector SVG export remains available rather than silently downsampling a file labelled as print resolution. RGB previews, nominal paper thickness, assembly/board clearances and food-safe production require physical proofing.

Coverage: `hingedPackaging.test.ts` checks all 16 new presets' cut area, connectivity, fold coordinates, exact assembled bounds/normals, flat UV alignment, six-face mapping, native artwork/import round trips, project scoping and print limits. Browser coverage exercises section separation, custom-family creation on Arabic/English mobile, pizza resize/save/reopen/3D/SVG, and transient actual-model thumbnail rendering alongside the existing carton regressions.

### Designer-wide light/dark appearance

The shared navbar offers an accessible light/dark toggle on all graphic-designer dashboard pages and in the editor. `DesignerThemeProvider` saves one small preference (`designcraft_theme_v1`); a blocked/full browser store does not disable toggling. Light is the default. The document-scoped attribute also themes body-mounted file/color popovers. It does not affect other UniTool apps.

The user-supplied image is served locally as `/images/packaging/daylight-background.jpg`, with a darker mint/beige UI overlay than the original packaging-only theme. Navigation, template setup, editor controls, storage and panels use readable light surfaces. Night mode restores the dark UI, including packaging. Artwork, swatches, SVG and 3D textures are never filtered or recolored; switching does not call canvas APIs, dirty a design or save anything to its native artwork JSON.

`designerTheme.spec.ts` covers all dashboard tabs, mobile sizing, editor pixel equality and native JSON equality across theme changes, reload persistence, English labels and unavailable preference storage. `packagingDaylight.spec.ts` covers the supplied background and shared daylight palette.

UI surfaces in the designer component CSS now use shared `--studio-ui-*` tokens with their exact original night colors as fallbacks, rather than relying solely on a partial list of theme selectors. This includes the properties dock, portal menus, crop toolbar, storage and packaging dialogs. The loading screen also follows the saved preference. Template preview art is explicitly marked `data-theme-art`. `daylightAudit.spec.ts` visits dashboard sections, library tabs, selected-object properties, file portals, resize and print dialogs on both mobile and desktop, rejecting visible dark-neutral UI surfaces while exempting authored media and intentional dimming scrims.
